# DDD Builder: DDD 목적·방법론·UI 검토

검토일: 2026-10-08. 대상: 도메인 탐색부터 구현 체크리스트까지의 실제 화면, 서버·MCP 계약, 온라인 주문 서비스 보드(93개 카드). 검토용 데이터는 실제 보드의 복사본으로 준비했다. 업무 규칙의 사실 여부는 사용자 확인 범위를 넘어 확정하지 않았다.

## 판단

DDD Builder는 협업으로 문제·언어·사건·경계·불변식을 정리하는 도구로 목적에 부합한다. 이번 변경으로 카드 간 인과관계와 합의 근거를 남길 수 있다. 다만 카드 작성만으로 DDD 설계가 완성되거나 올바른 컨텍스트·트랜잭션 경계가 증명되지는 않는다. 운영 가능한 도메인 모델까지 가려면 담당자의 실제 사례 검토와 구현 시나리오 검증이 필요하다.

## 방법론 해석

[Eric Evans의 DDD Reference](https://www.domainlanguage.com/ddd/reference/)를 기준으로 컨텍스트는 언어와 모델의 적용 범위, 애그리게이트는 일관성을 지키는 경계로 검토했다. 여러 컨텍스트의 상태를 하나의 루트가 직접 변경하는 설명은 피해야 한다. 컨텍스트 간 협업은 각자의 책임과 통합 계약을 구분하여 설명해야 한다.

[EventStorming의 Incremental Notation](https://www.eventstorming.com/patterns/incremental-notation/)을 기준으로 처음부터 모든 표기와 경계를 채우게 하지 않는다. 먼저 사건과 논쟁 지점을 탐색하고, 필요할 때 명령·정책을 보강하며, 상세 설계에서 일관성 경계를 확인한다. Big Picture·Process Modelling·Software Design은 목적과 상세 수준이 다르므로 현재의 다섯 단계가 공식 방법론 전체를 자동으로 수행한다고 주장하지 않는다.

설계 점검은 입력·연결의 빈틈을 찾는 보조 기능이다. 연결되지 않은 명령이 탐색 초기에는 자연스러울 수 있고, 같은 이름의 카드가 의도된 것일 수도 있다. 따라서 점검 항목이 남아 있어도 단계 이동이나 저장을 차단하지 않는다. 합의에는 자유 형식의 근거가 필요하지만 모든 담당자의 서명·승인을 검증하는 기능은 아니다.

## 반영한 UI와 데이터 동작

1. 이벤트·컨텍스트에서 카드 보기와 흐름 보기를 전환한다. 흐름 방향, 반환 연결, 아직 연결되지 않은 카드와 필터로 숨겨진 대상을 구분한다. 화살표 외에도 읽을 수 있는 연결 목록을 제공한다.
2. 검색·검토 상태·컨텍스트·정상/예외 필터와 표시 건수를 제공한다. 필터가 켜진 상태의 순서 이동은 비활성화하여 숨겨진 카드 사이에서 잘못 이동하지 않게 한다.
3. 컨텍스트 관계의 설명 텍스트와 Mermaid 원문을 독립적으로 저장한다. 전환해도 원문을 잃지 않는다. 편집 중 미리보기와 저장 후 카드·조회 화면의 다이어그램을 제공한다. 원문을 펼쳐 확인할 수 있고 문법 오류를 보여 주어도 작성한 내용을 지우지 않는다.
4. Mermaid는 설명용 시각화다. 다이어그램 노드와 실제 카드 ID의 연결을 자동 추정하지 않는다. 카드 흐름과 다이어그램을 별도로 수정해야 한다는 안내를 문서에 명시했다.
5. 저장 중 입력을 비활성화하고 현재 충돌 검사를 유지한다. 조회 권한에서는 편집 대신 상세 화면을 연다. 예전 카드에 새 필드가 없더라도 서버와 화면이 기본값을 제공하여 읽을 수 있다.
6. 제목·세부 입력 한도를 서버와 맞추고 필터·편집 필드에 접근성 이름을 제공한다. 키보드 초점과 모바일 화면의 가로 넘침을 확인했다.

Mermaid는 필요할 때 로드한다. [Mermaid 공식 보안 설정](https://mermaid.js.org/config/usage.html)에 따라 strict 모드를 적용하고 생성한 SVG도 정리한다. 문서 내 설정 지시문, 클릭 링크와 외부 이미지·리소스를 허용하지 않는다. 설정을 바꾸어야 하는 특수 다이어그램은 현재 지원하지 않는다.

## 온라인 주문 서비스 보드의 남은 논의

확인된 사업은 자사 상품 쇼핑몰이다. 실물 상품, 전체 주문 이행, 선예약 후결제는 설계 제안이며 사용자와 합의한 업무 사실로 승격하지 않는다. 예약 기한, 취소 제한 시점, 부분 배송·취소, 반품·가격 계산의 경계와 운영 대응은 담당자 확인이 필요하다. 주문·결제·재고·배송의 네 컨텍스트와 다섯 애그리게이트는 이 가정에 대한 초안이다.

카드의 설명을 흐름 연결과 정상·예외 태그로 보강하고, 컨텍스트의 관계 설명은 보존하면서 Mermaid 표현을 추가할 수 있다. 결제 승인과 재고 할당 완료를 모두 기다리는 정책처럼 여러 입력이 필요한 경우에는 정책 본문에서 조건을 확인해야 한다. 화살표만 보고 모든 후속 명령이 즉시 실행된다고 해석하면 안 된다.

| 우선순위 | 과제                                                       | 이유                                                                                                            |

| 높음     | 연결의 조건·상관관계·중복 처리·타임아웃을 구조화           | 여러 입력을 기다리는 정책과 예외 조건이 현재는 설명 텍스트에 있다.                                              |
| 높음     | 도메인 사례와 합의 근거의 직접 연결                        | 가설을 실제 사례로 검증하고 변경 영향과 근거를 찾아야 한다.                                                     |
| 중간     | Context Map의 협력 패턴·팀 책임·핵심/지원/일반 도메인 분류 | Mermaid로 표현할 수 있지만 구조적으로 저장하고 점검하는 필드는 없다.                                            |
| 중간     | 읽기 모델·외부 시스템의 명시적 표기                        | 현재 행위자·설명으로 나타낸다. 소프트웨어 설계 워크숍의 표기 범위를 확장할 수 있다.                             |
| 중간     | 큰 그래프의 확대·축소·자유 배치와 Mermaid 로딩 최적화      | 필터와 스크롤은 제공하지만 많은 연결이 한 화면에 몰리면 탐색 비용이 높다. Mermaid의 일부 지연 로딩 청크도 크다. |
| 중간     | 질문의 답변·해결 상태를 검토 상태와 분리                   | 현재 미합의 질문을 미해결로 집계한다. 합의와 답변 여부가 항상 같지는 않다.                                      |

이 과제들을 해결했다고 DDD 품질을 점수화할 수 있는 것은 아니다. 실제 도메인 담당자와의 워크숍, 모델의 행동과 변경 비용이 판단 근거다.

## 2026-10-09 후속 UI 반영: 컨텍스트 경계 지도

컨텍스트 카드와 개별 다이어그램만으로는 어떤 모델이 같은 경계에 속하는지 읽기 어려웠다는 피드백을 반영했다. 컨텍스트 나누기의 기본 화면을 경계 지도로 바꾸고, 점선 영역 안에 이벤트·명령·정책·애그리게이트를 묶었다. 실제 `contextId`가 소속을 결정하며 제목이나 Mermaid로 추정하지 않는다. 빈 영역과 미분류 공간도 유지한다.

실제 카드 흐름에서 경계를 넘는 연결을 집계하고, 원본 카드와 방향별로 펼칠 수 있다. 흐름이 있는 연결의 화살표는 실제 흐름 방향만 나타내고, 별도로 선언한 관계만 있는 연결은 점선으로 표시한다. 조회자는 상세를 읽고 편집자는 내부 카드의 배치를 바꿀 수 있다. 필터는 내부 카드에 적용하며 모바일에서는 영역·연결 목록을 세로로 제공한다.

후속 검증: 서버·모델 테스트 71개, 전체 브라우저 테스트 16개 통과. 소속과 연결 집계, 빈 경계, 검색, 카드 재배치·새로고침, 조회 권한, 모바일 가로 넘침을 포함했다. 새 지도가 컨텍스트 분리의 업무적 정당성을 자동으로 증명하지는 않는다.

## 초기 검증 기록

- 서버·저장·인증·MCP 테스트 70개 통과. 기존 카드 호환, 합의 상태 변경, 연결 문법·소유권, 삭제 정리, revision 충돌, 텍스트·Mermaid 저장과 내보내기를 포함한다.
- 전체 브라우저 테스트 15개 통과(Chromium, 데스크톱 1440×1000, 모바일 390×844). 편집·필터·흐름·점검·새로고침, 독립 원문 보존, 문법 오류, 외부 리소스 차단, 조회 권한과 기존 워크숍 동작을 확인했다.
- TypeScript/Vite 빌드 통과. Mermaid는 지연 로딩하며 일부 다이어그램 청크의 크기 경고가 남는다.
- 의존성 감사에서 보고된 취약점 0개. Mermaid의 KaTeX 전이 의존성을 패치 버전으로 제한했다.
- 실제 93개 카드 복사본에서 컨텍스트 편집과 다이어그램, 정상·예외 흐름을 추가로 화면 검토했다. 자동화 테스트는 업무 규칙의 사실 여부나 모든 브라우저 지원을 증명하지 않는다.
