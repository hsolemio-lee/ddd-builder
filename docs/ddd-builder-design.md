# DDD Builder — 첫 버전 설계 제안

상태: 단계별 협업 설계 보드 범위 확정 · 2026-10-07

## 목표

한 사람이 자신의 컴퓨터에서 서버를 실행하고, 같은 네트워크에 있는 팀원이 브라우저로 접속해 도메인 주도 설계를 함께 진행한다. 처음 사용하는 사람도 다음에 무엇을 정리해야 하는지 알 수 있는 작은 도구를 만든다.

## 추천 접근과 대안

1. **단계별 협업 설계 보드 (추천)**: 안내 문구와 카드 중심으로 진행한다. 자유로운 화이트보드보다 구현과 사용이 단순하며, 설계 결과를 다시 읽기 쉽다.
2. **이벤트 스토밍 화이트보드**: 자유 배치가 유연하지만, 확대·이동·카드 좌표·동시 이동 처리 때문에 화면과 구현이 복잡해진다.
3. **설계 및 코드 생성 도구**: 구현 시작을 도울 수 있지만, 대상 언어·프레임워크·생성 규칙을 먼저 정해야 한다. 첫 버전 이후 확장으로 적합하다.

## 추천 버전의 화면과 작업 흐름

- 입장: 표시 이름과 공유 접속 코드를 입력한다. 개인 계정 없이 팀원이 같은 작업 공간에 참여한다.
- 프로젝트 목록: 프로젝트를 만들고 제목과 목적을 정리한다.
- 프로젝트 작업 화면: 왼쪽 단계 목록, 가운데 카드 보드, 오른쪽 선택한 카드의 편집 영역을 둔다.
- 상단: 현재 접속자, 연결 상태, 공유 주소, 결과 내보내기를 표시한다.

### 다섯 단계

1. **도메인 탐색**: 해결할 문제, 주요 사용자, 공통 용어를 정리한다.
2. **이벤트 정리**: 도메인 이벤트, 명령, 행위자, 정책, 미해결 질문을 카드로 기록한다. 카드의 순서를 변경할 수 있다.
3. **바운디드 컨텍스트**: 컨텍스트를 만들고 이벤트 카드를 분류한다. 컨텍스트의 책임과 다른 컨텍스트와의 관계를 기록한다.
4. **애그리게이트 설계**: 소속 컨텍스트, 루트, 엔티티, 값 객체, 지켜야 할 규칙을 정리한다.
5. **구현 준비**: 작업 항목을 만들고 담당자와 완료 상태를 정리한다.

단계는 자유롭게 오갈 수 있다. 입력을 완료해야 다음 단계로 이동할 수 있는 강제 조건은 두지 않는다. 처음 만든 프로젝트에는 수정·삭제 가능한 작은 주문 예시를 제공한다.

## 협업과 저장

- 각 카드에는 고유 ID와 수정 버전을 둔다. 서버가 저장을 완료한 변경만 모든 참여자에게 전달한다.
- 다른 카드를 동시에 수정할 수 있다. 같은 카드의 이전 버전을 저장하면 덮어쓰지 않고 충돌을 알리며 최신 내용을 확인할 수 있게 한다.
- 일시적으로 연결이 끊기면 연결 상태를 표시한다. 다시 연결되면 서버의 현재 데이터를 받아 누락된 변경을 반영한다.
- 서버가 로컬 SQLite 데이터베이스에 프로젝트와 카드, 작업 항목을 저장한다. 재시작해도 작업이 유지된다.
- 접속자 목록은 현재 연결을 기준으로 관리하며, 끊어진 참여자는 제거한다.
- 프로젝트별로 Markdown 결과와 JSON 백업을 다운로드한다. JSON에는 접속 코드나 인증 정보를 포함하지 않는다.

## 실행 구조

- React 및 TypeScript 화면, Node.js API 서버, SQLite 저장소로 구성한다.
- 변경 요청은 HTTP API로 처리하고, 서버 이벤트 스트림으로 저장된 변경을 전달한다.
- 개발 화면과 실행용 서버 모두 다른 팀원이 접속 가능한 호스트 바인딩을 지원한다. 실행용 서버는 빌드된 화면과 API를 하나의 포트에서 제공한다.
- 서버 시작 시 localhost 주소, 사용 가능한 로컬 네트워크 주소와 접속 코드를 보여준다. 접속 코드는 서버의 파일에 보관하여 재시작해도 유지한다.
- 모든 데이터 API와 이벤트 스트림에 접속 코드를 검사한다. 사용자 표시 이름은 화면 표시 용도로만 사용한다.
- 서버가 켜져 있고 네트워크에서 해당 포트에 접근할 수 있어야 참여할 수 있다. 첫 버전은 같은 로컬 네트워크 사용을 대상으로 한다. 인터넷 공개 배포와 외부 네트워크 연결 설정은 포함하지 않는다.

## 검증 기준

- 서로 다른 두 브라우저 세션에서 프로젝트 및 카드의 생성·편집·삭제가 공유된다.
- 같은 카드를 동시에 수정하면 이미 저장된 변경을 덮어쓰지 않는다.
- 서버 재시작 뒤에 프로젝트와 작업 항목을 다시 불러올 수 있다.
- 연결 복구 후 데이터와 접속자 표시가 현재 서버 상태와 일치한다.
- 잘못된 접속 코드로 데이터에 접근할 수 없다.
- 단계 탐색, 카드 편집, 컨텍스트 분류, 애그리게이트 작성, 작업 완료, 내보내기를 실제 화면에서 확인한다.
- README에 설치, 실행, 다른 컴퓨터에서 접속, 데이터 위치와 백업 방법을 설명한다.

## 첫 버전 이후

자동 코드 생성, 자유 배치 캔버스, 채팅, 역할별 권한, 외부 로그인, 변경 이력과 복원은 별도 확장으로 남긴다.

## 추가 확정 범위: 외부 AI와 MCP 협업

stdio MCP 서버가 같은 HTTP API를 통해 보드를 읽고 수정한다. 기본 읽기 전용이며, 연결 설정의 DDD_READ_ONLY=false로 카드 추가·수정 도구를 켤 수 있다. 프로젝트 목록과 단계별 보드 읽기, 프로젝트 리소스, 이벤트 스토밍 분석 프롬프트를 제공한다. 앱에서 실행 경로와 접속 정보를 포함한 설정, 프로젝트 ID를 포함한 분석 요청을 복사한다. 수정은 기존 카드의 revision으로 검사하고, 사람의 변경을 덮어쓰지 않는다. 모델 실행은 외부 클라이언트가 담당한다. 로컬 클라이언트의 stdio 연결을 대상으로 하며, 공개 HTTP MCP 엔드포인트는 범위에 포함하지 않는다.
