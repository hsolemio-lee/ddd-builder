# MCP에서 내 모든 프로젝트 접근

상태: 2026-10-20 사용자 승인. 구현 및 검증 대상.

## 목표

한 MCP 연결에서 로그인 계정이 현재 멤버로 참여하는 모든 프로젝트를 조회한다. HTTP와 stdio 모두 같은 권한 검사를 사용한다. 운영 관리자라는 이유만으로 참여하지 않은 프로젝트에 접근하지 않는다.

## 접근 방식

추천은 기존 프로젝트 전용 토큰을 유지하면서 새 토큰의 대상에 `내 모든 프로젝트`를 추가하는 것이다. 기존 연결의 권한을 의도치 않게 확대하지 않고 필요한 계정 연결을 새로 만들 수 있다.

기존 토큰을 모두 계정 범위로 바꾸는 대안은 설정 변경이 적지만 이미 외부 AI에 전달된 자격 증명까지 확대한다. 토큰마다 프로젝트 목록을 저장하는 대안은 세밀하지만 새 프로젝트마다 토큰을 수정해야 하므로 이번 요구에 적합하지 않다.

## API와 저장

`POST /api/tokens`의 `projectId`는 기존 문자열 또는 명시적인 `null`을 받는다. 문자열은 해당 프로젝트만, `null`은 계정이 현재 접근할 수 있는 모든 프로젝트를 뜻한다. 누락·빈 문자열·다른 타입은 거부한다. 응답과 토큰 목록에도 같은 의미의 `projectId`를 제공한다.

기존 SQLite `auth_tokens.project_id`의 NOT NULL 제약을 제거하는 원자적 마이그레이션을 적용한다. 나머지 열 순서와 해시·만료·외래 키 제약은 유지하고 기존 행은 프로젝트 범위를 보존한다. 계정 토큰은 특정 프로젝트 삭제와 함께 삭제되지 않는다. 구버전은 계정 토큰의 프로젝트 접근을 거부하므로 롤백 때 권한이 확대되지 않는다.

## 권한

계정 토큰의 목록·보드·카드·문서·내보내기·MCP 리소스는 현재 프로젝트 멤버십으로 필터링한다. 신규 참여 프로젝트는 다음 요청부터 포함하고 멤버십 철회는 다음 요청부터 제외한다. 다른 프로젝트 ID를 직접 요청해도 데이터를 노출하지 않는다.

읽기 토큰은 모든 대상에서 읽기만 허용한다. 쓰기 토큰도 현재 편집자·관리자인 프로젝트의 카드만 편집할 수 있으며 조회자 프로젝트에는 쓰지 못한다. 계정 범위 쓰기 토큰 발급에는 현재 편집 가능한 프로젝트가 하나 이상 필요하다. 계정·멤버·프로젝트 관리 기능은 계속 금지한다. 게스트는 토큰을 발급하거나 MCP로 접속할 수 없다.

토큰의 최대 30일 만료, 기본 읽기, 해시 저장, 일회성 원문 표시, 즉시 철회 및 계정 차단 정책을 유지한다. 토큰 생성·철회는 기존 감사 기록과 같은 트랜잭션에서 처리한다.

## 화면과 연결

외부 AI 연결에 대상 선택을 추가하며 새 발급의 기본 대상은 `내 모든 프로젝트`, 권한은 읽기다. `현재 프로젝트만`도 선택할 수 있다. 계정 토큰은 어느 프로젝트에서 창을 열어도 내 연결에 표시하며 각 토큰의 접근 대상을 명시한다. 기존 프로젝트 토큰은 해당 프로젝트에서 표시한다.

계정 토큰은 이후 참여하는 프로젝트에도 접근한다는 안내를 표시한다. 기존 토큰으로 연결된 AI에는 새 계정 토큰을 발급해 설정의 Bearer 토큰 또는 `DDD_TOKEN`을 교체해야 한다. MCP URL·포트·도구 이름은 바꾸지 않는다.

## 검증과 배포

먼저 실패하는 회귀 테스트로 계정 범위 목록, 서로 다른 역할, 다른 계정의 비공개 프로젝트 차단, 멤버십 추가·철회, 토큰 만료·철회·차단, 프로젝트 삭제, 기존 프로젝트 토큰 격리와 DB 마이그레이션을 확인한다. HTTP MCP와 stdio에서 목록과 보드·문서 접근을 검증하고 화면에서 대상 선택·토큰 표시를 검증한다.

README와 보안 API 계약을 변경된 발급 방식에 맞춘다. 관련 테스트·빌드·기존 검사 후 저장소에 반영하고, 기존 로컬 Docker 서비스를 백업·복원 검증 후 재배포한다. 실제 운영 데이터나 기존 토큰의 범위를 자동으로 바꾸지 않는다.
