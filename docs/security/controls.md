# 보안 통제와 출시 판정

이 문서는 구현 상태와 운영자가 완료해야 하는 조건을 구분한다. 문서 작성이나 단위 테스트 통과만으로 공식 서비스 운영 승인을 뜻하지 않는다. OWASP ASVS 5.0을 검토 기준으로 사용하며 인증 또는 전체 요구 사항 충족을 주장하지 않는다.

| 통제                                                            | 상태                                                       | 검증 또는 완료 조건                                                                            |
| --------------------------------------------------------------- | ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| HTTPS와 Secure·HttpOnly·SameSite 세션 쿠키                      | 기존 구현                                                  | Funnel 공개 주소에서 확인, 잘못된 Origin 차단                                                  |
| CSP·프레임 차단·권한 정책·HSTS                                  | 구현·테스트 완료                                           | 실제 HTTP 응답 테스트, HSTS는 HTTPS 주소에서만 적용                                            |
| 요청·로그인·쓰기·SSE·세션 수 제한                               | 구현·테스트 완료                                           | 제한 초과 429, 만료 후 회복, 기존 연결 보존 테스트                                             |
| Docker 루프백 바인딩·읽기 전용 파일시스템·비루트 실행·자원 제한 | 구현·테스트 완료                                           | Docker 통합 테스트와 실제 운영 Compose 확인                                                    |
| 개인별 인증·초대·계정 철회                                      | 구현·시험 및 실제 Google 관리자 로그인 검증 완료 | 복제 데이터와 운영 서버에서 최초 관리자·기존 프로젝트 권한 확인, MFA는 별도 운영 조건                                            |
| 프로젝트별 관리자·편집자·조회자                                 | 구현·테스트 완료                                           | REST·내보내기·SSE·참여자 목록의 권한 우회 차단                                                 |
| 프로젝트별 게스트 초대·개별 세션                                 | 구현·테스트 완료, 운영 배포 별도                            | 1회용 코드·동시 사용·만료·프로젝트 격리·권한 변경·철회·SSE 종료·관리자/MCP 접근 차단 검증      |
| MCP 토큰 해시·프로젝트 범위·읽기/쓰기 분리                      | 구현·테스트 완료                                           | 직접 HTTP 요청에도 같은 권한 강제, 만료와 철회 검증                                            |
| 감사 로그                                                       | 구현·테스트 완료                                           | 행위 주체·대상·결과 기록, 변경과 감사 기록의 원자적 저장·실패 시 롤백, 비밀값과 카드 본문 제외 |
| 의존성·비밀값 CI 검사                                           | 설정·검사 완료                                             | GitHub에서 검사 성공, 높은 심각도 취약점 출시 차단                                             |
| 운영자 MFA·복구 절차                                            | 운영자 설정 필요                                           | IdP 관리자 MFA, 최소 2명 담당자, 복구 훈련                                                     |
| 암호화된 외부 백업·복원 검증                                    | 운영자 설정 필요                                           | 일별 백업 30일 보관, 월별 복원 기록                                                            |
| 경보·보안 연락처·개인정보 고지                                  | 운영자 설정 필요                                           | 실제 연락처, 공급자·저장 지역·보유 기간 확정                                                   |

현재 공유 접속 코드 모드는 개발과 제한된 워크숍용이다. 개인 인증과 권한, 감사 기록의 코드 검증을 통과했더라도 실제 공급자 설정과 운영 조건을 모두 완료하기 전에는 공식 서비스 준비 완료로 표시하지 않는다.

2026-10-07 현재 공개 배포는 Google OIDC의 `production` 모드로 전환했다. 실제 로그인과 데이터 보존 검증은 [인증 설정 기록](identity-setup.md)에 남겼다. 위 표의 운영자 설정 항목은 여전히 공식 출시 차단 조건이다.

운영 절차는 [operations.md](operations.md), 데이터 처리 기준은 [privacy.md](privacy.md), 제보 및 출시 기준은 [SECURITY.md](../../SECURITY.md)를 따른다.
