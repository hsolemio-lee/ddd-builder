# AI 구현을 위한 컨텍스트별 도메인 문서

DDD Builder의 **결과 내보내기 → 구현 문서 묶음 ZIP**은 현재 보드를 컨텍스트별 문서로 변환한다. 프로젝트 전체 또는 하나의 컨텍스트를 선택하고 생성 문서를 미리 볼 수 있다. 기존 단계별 워크숍 기록 Markdown과 JSON 백업도 유지한다.

이 구성은 실무용 작성 제안이다. 특정 문서 형식의 AI 정확도나 생산성을 보장하는 표준으로 취급하지 않는다. 보드를 원본으로 관리하며 설명 문서와 JSON을 같은 데이터에서 생성한다. 구현하면서 발견한 차이는 보드에 반영하고 다시 내보낸다.

## 생성되는 문서

```text
AGENTS.md
  문서 탐색, 작업별 읽기 기준, 변경과 검증

docs/domain/
  index.md
  context-map.md
  document-data.json
  unassigned.md                 # 프로젝트 전체 묶음에만 포함
  context-{contextId}/
    context.md
    glossary.md
    rules.md
    scenarios.md
    aggregates.md
    implementation.md

docs/adr/
  index.md                      # ADR 작성 안내
```

디렉터리는 제목 대신 컨텍스트 ID로 고정한다. 컨텍스트의 이름이 바뀌거나 같은 이름이 여러 개 있어도 문서 경로는 유지된다. 카드 ID, revision, 마지막 변경과 검토 근거를 기록하며, 규칙 ID와 사례 ID는 소유 애그리게이트 ID와 함께 추적한다. 문서에 사용한 경계 밖 참조의 ID와 revision도 `generatedFrom.references`에 기록한다.

`AGENTS.md`는 내보낸 문서 묶음의 진입점이다. 기존 저장소에 적용할 때 팀의 AGENTS.md와 통합하고 실제 문서 경로를 확인한다. 이 기능은 사용자의 코드 저장소에 파일을 직접 쓰거나 기존 지침을 덮어쓰지 않는다.

## 먼저 작성할 최소 묶음

1. **책임과 경계**: 컨텍스트의 책임과 역할을 설명에 적고, ‘구현 문서용 상세 항목’에서 목적·책임 밖의 일·소유 데이터와 규칙·외부 의존성을 기록한다.
2. **용어집**: 도메인 탐색의 공통 용어 카드에 소속 컨텍스트를 지정한다. 설명은 정의로 사용하고, 코드명·구별 사례·혼동 용어·정의의 출처를 추가한다. 같은 제목이라도 컨텍스트가 다르면 별개의 의미로 유지한다.
3. **규칙**: 애그리게이트의 업무 규칙에 처리 명령을 연결한다. ‘규칙의 적용 조건·예외·근거’에서 적용 대상·범위, 조건, 위반 결과, 예외·대안, 미결정 사항과 출처를 기록한다.
4. **사례**: 각 규칙에 정상·거절·경계값·동시성 사례의 Given/When/Then을 기록한다. 성공 여부뿐 아니라 실패 시 기존 상태와 이벤트의 변화를 관찰할 수 있게 작성한다.

복잡한 부분에는 애그리게이트 상태 전이와 트랜잭션 경계, 외부 참조와 조정·실패 정책을 추가한다. 컨텍스트의 연동 계약은 상대·방향·소유자·용어 변환·API/이벤트·실패 처리·버전 정책을 자유 입력으로 기록한다. 현재 연동 계약은 개별 계약을 검증하는 구조화 스키마가 아니다.

구현 과제에는 완료 확인 기준과 실제 테스트 위치를 기록한다. 규칙의 사례에도 테스트 위치를 연결할 수 있다. 테스트 경로나 완료 체크는 테스트 실행 성공의 증거가 아니다. 코드를 구현한 저장소에서 실제 검증을 수행한다.

## 확인되지 않은 내용을 보존하는 방법

- 빈 항목은 ‘미작성’으로 출력한다. 생성기가 실제 정책이나 코드 이름을 추측해 채우지 않는다.
- 미결정 사항은 질문으로 유지한다. 업무 담당자가 확인하기 전에는 합의된 정책으로 간주하지 않는다.
- 규칙 상태는 가설·제안·합의·폐기 중 선택한다. 생략하면 애그리게이트 상태를 따른다고 명시한다. 카드 합의에는 기존 검토 근거 계약을 적용한다. 합의된 규칙의 내용을 부분 수정하면 명시적인 재합의가 없는 경우 제안으로 돌아간다. 폐기된 규칙은 현재 구현 요구사항으로 사용하지 않는다.
- 입력 도움말과 가상의 주문·생산계획 예시는 사용자 데이터로 저장하지 않는다. 학습 가이드는 문서 묶음에 가상 정책을 삽입하지 않는다.
- 컨텍스트가 없는 용어와 탐색 기록은 전체 묶음의 `unassigned.md`에 보존한다. 제목·관계·Mermaid 그림만 보고 소속을 자동 배정하지 않는다.
- 컨텍스트 맵은 기록된 연결의 종류와 방향을 구분한다. ‘관련’과 ‘선행 조건’ 화살표를 데이터 전달 방향이나 Upstream/Downstream으로 해석하지 않는다.
- 자유 입력 불변조건은 원문을 유지하며, 구조화 규칙으로 자동 분해하거나 합치지 않는다.
- 현재 ADR은 작성 안내만 제공한다. 카드의 합의 근거에서 결정·대안·결과·재검토 조건을 추측해 완성된 ADR을 만들지 않는다.

## MCP로 필요한 문서 선택하기

읽기 도구 `get_domain_documents`는 웹 미리보기·ZIP과 동일한 문서를 조회한다. 전체 묶음 대신 진입 문서부터 읽고 작업 컨텍스트와 필요한 경로를 선택한다.

```json
{
  "projectId": "project-id",
  "path": "docs/domain/index.md"
}
```

```json
{
  "projectId": "project-id",
  "contextId": "context-id",
  "path": "docs/domain/context-context-id/rules.md"
}
```

`path`는 파일 시스템 경로가 아니라 생성된 문서 목록의 정확한 경로다. 응답은 `schemaVersion`, `projectId`, `contextId`, `generatedFrom`, `files`를 포함하며, 각 파일은 `path`, `title`, `mediaType`, `content`를 갖는다. 특정 경로를 선택하면 `files`에는 해당 파일 하나만 포함한다.

- `ddd://projects/{projectId}/documents`: 프로젝트 전체 문서 리소스
- `ddd://projects/{projectId}/contexts/{contextId}/documents`: 컨텍스트 문서 리소스
- `ddd://guides/domain-documents`: 문서 작성·운영 가이드와 가상의 생산계획 사례
- `ddd://learning/aggregates`: 애그리게이트 항목별 예시와 동일한 문서 운영 가이드

도구와 프로젝트 리소스는 기존 API를 통해 현재 프로젝트 권한을 검사한다. 공개 학습 리소스에는 실제 프로젝트 데이터가 없다. 읽기 토큰으로 문서를 조회할 수 있지만 보드를 수정할 수 없다.

`create_card`와 `update_card`의 `data`는 새 문서 항목도 지원한다. 카드 종류에 맞는 항목만 서버에서 허용하며 `data` 객체는 제공하면 전체 교체이므로 기존 필드를 읽고 보존한다. 규칙의 조건·위반 결과·예외·출처 등은 `patch_aggregate_design`의 `upsertRules`로 부분 수정하고, 사례의 `testReferences`는 `upsertExamples`로 부분 수정한다. 최신 revision과 기존 충돌 검사를 적용한다.

## 반복해서 운영하기

한 기능의 관련 문서와 기존 코드를 함께 제공한다. 정상·실패 사례와 불변조건을 작은 구현 단위로 검증하고, 문서의 의도와 현재 구현이 다르면 차이를 기록한다. 같은 변경에서 원본 보드와 구현을 갱신하고 문서를 다시 생성한다. 현재 기능은 생성 문서를 코드 저장소와 자동 동기화하거나 테스트 실행 결과를 수집하지 않는다.
